## What I generated

**`infra/bootstrap/`** is the one-time account stack, applied once from a laptop. It creates the versioned, encrypted state bucket with S3-native locking, the GitHub OIDC provider, five CI roles, the ECR repository, and a monthly cost budget that emails at 80% actual and 100% forecast.

**`infra/app/`** is a single root module applied three times. Each environment gets its own VPC, ECS Fargate service, ALB, RDS Postgres, and `DATABASE_URL` secret. The only things that differ between environments are in `infra/app/envs/<env>.tfvars`, so a reviewer can diff those three files and know the complete delta.

**`infra/modules/`** holds the three building blocks: network, database, and service.

**`.github/workflows/`** contains three workflows. Pull requests build the image without pushing, run format and validate with no credentials, then plan all three environments with a read-only role and post the plan as a PR comment. Pushes to main build one arm64 image tagged with the git SHA, then promote that same image through dev, stg, and prd. Each stage is a GitHub Environment, and the prd deploy role only trusts tokens from jobs bound to the prd environment, so the required-reviewers gate is enforced by AWS trust policy, not just GitHub.

**`COSTS.md`** is the estimate. **`infra/README.md`** is the reviewer guide.

## Key assumptions

- Single AWS account in us-east-1. A public Route 53 hosted zone for your domain already exists. Placeholders to replace: the GitHub repo in `infra/bootstrap/terraform.tfvars`, the account ID in the backend files, and `example.com` hostnames.
- The app needs only Postgres. No cache, queue, or object store exists because the code uses none.
- No NAT gateway. Tasks have security-group-protected public IPs. The database sits in private subnets with no internet route. The `enable_nat_gateway` toggle flips this for about $33 per month per environment.
- Prd RDS is single-AZ with 7-day backups and deletion protection. Multi-AZ is a one-line toggle.
- The DB password is generated by OpenTofu and therefore lives in encrypted state. The README documents the write-only-attribute upgrade path if that is unacceptable.
- Graviton everywhere: ARM64 Fargate and `db.t4g` instances. The Dockerfile has no `RUN` steps, so the cross-platform build in CI is fast.
