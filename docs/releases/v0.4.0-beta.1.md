# v0.4.0-beta.1 — Know what you're shipping. Know what it costs.

Neckbeard's first 0.4 beta brings a more useful starting point for real apps: understand the processes, generate infrastructure you can review, and put explicit usage assumptions next to the monthly estimate.

The biggest change is the estimator. A real Umami deployment exposed costs we had missed and numbers we had already published. We withdrew those figures, wrote the postmortem, and fixed the model across AWS, Azure and all three Kubernetes targets. This beta ships those repairs and the evidence behind them.

## What's new

### Cost estimates that account for the actual workload

The estimator now includes running-task floors, always-on workers, scheduled-job duration, network transfer, managed ingress, public IPs, node disks and provider-specific database costs. Azure Container Apps separates active compute, idle replicas and requests; Kubernetes uses total node bounds and explicit additional node-hours. Azure Postgres includes standby and replica costs. Spot pricing follows each cloud's model.

Idle, low, expected and high scenarios show their assumptions. Prices are looked up in the requested currency, with explicit checks for product and billing-unit mismatches. Missing billable components remain partial and cannot approve a spending estimate. Ceiling approvals now bind to the effective Terraform inputs, blueprint and cost-model version; changing those inputs invalidates approval.

We checked **48 pricing scenarios across six cloud/runtime combinations in USD and EUR**. Twelve sanitized expected-scenario snapshots run offline in the test suite. These are pricing checks, not invoice matching or proof that every deployment path works.

### Disco, with Redis alongside your app

`/neckbeard:disco` adds an experimental self-hosted deployment target. A Bellwether trial exercised deployment, Postgres, a worker, scheduled execution, an update with preserved data, and cleanup.

Redis can now be provisioned as a password-protected, persistent companion on the Disco server's private network, with no published host port. Its setup preserves data across app redeploys. This is a single-server companion, with documented capacity, backup and recovery limits; managed Redis on AWS, GCP and Azure is not included. Redis setup and graceful recreation were tested locally; the Redis companion has not yet been exercised on a live Disco server.

Thanks to the Disco contributor for Neckbeard's first outside contribution, and to Disco's creator for helping make the integration testable.

### Better onboarding, and a real GCP app

Procfile detection distinguishes HTTP, worker and scheduled roles, retains command evidence for review, and excludes release/migration hooks. The onboarding guide now explicitly reviews persistent data, build context, listeners and health probes before cloud setup.

A real Umami deployment on GCP exercised generated bootstrap and foundations, database preparation, scanned image build, trusted HTTPS, analytics writes/reads, persistence after a revision replacement, and a generated release workflow. That trial also produced the fixes for Cloud Run public ingress under domain-restricted sharing and slow application startup.

## Install or upgrade

This is a **prerelease**. `go install @latest` and GitHub's latest stable release continue to select v0.3.0.

From the matching plugin checkout:

```sh
bash scripts/install.sh -v v0.4.0-beta.1 -f
```

Or install from source:

```sh
go install github.com/bealesh/neckbeard/cmd/neckbeard@v0.4.0-beta.1
neckbeard skill install -target codex
```

Use `-target cursor` for Cursor. Claude Code users should update both the plugin and CLI. The installer verifies release archives against `checksums.txt`; prebuilt archives cover macOS and Linux on amd64 and arm64.

Keep your refined profiles and configuration. Reinstall the skill after upgrading, then re-plan, re-estimate and review scaffold conflicts. Earlier cost approvals must be regenerated. Preserve user edits when resolving conflicts.

## Where the beta stands

The beta focus is onboarding: analyze, plan, estimate, scaffold, validate and the human-run bootstrap guide. Cloud deployment, promotion and recovery remain experimental. CI validates all six cloud/runtime lanes without cloud credentials; it does not deploy them. Full AWS/Azure/Kubernetes lifecycle and recovery coverage, GitLab deployment coverage and three independent-user trials remain outstanding. AWS/Azure slow-start follow-up is tracked in [#44](https://github.com/bealesh/neckbeard/issues/44).

Estimates exclude free allowances, discounts and taxes. A ceiling is a pre-scaffold estimate policy check, not a cloud spending cap. Review the named usage assumptions before accepting a total.

## Help shape the next beta

Try it against an app you know well. Check whether the process roles, persistent data, infrastructure and cost assumptions match your app before deploying. If something looks wrong, [file an issue](https://github.com/bealesh/neckbeard/issues/new) with the CLI/plugin version, cloud/runtime, expected behavior and a redacted transcript. Keep credentials, state files and raw authenticated plans out of reports.
