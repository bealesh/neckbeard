# GCP Umami trial — 2026-10-22

## Scope

Maintainer-operated trial of Umami upstream commit
`e92fdab99508a8ed05249f6c5f07e140deab79e1` (package 3.4.0) on the GCP
serverless-containers lane. One HTTP service on port 3000, private managed
PostgreSQL 17, Secret Manager, Artifact Registry and HTTPS load balancer.
Redis, ClickHouse and Kafka are optional upstream and are not enabled here.
Only dev is applied; generated stg/prd stacks remain unapplied.

The sandbox display name is `oss-sandbox`; its project ID is
`stock-oss-sandbox` because the shorter ID was globally unavailable. The
sandbox uses the existing Stock organization and billing account. No Stock
application resources or organization policies were modified.

## Organization-policy compatibility

The organization restricts IAM membership to its domain, so an `allUsers`
Cloud Run invoker grant would fail. Its effective policy permits disabling
the invoker IAM check. Google's [public access guidance](https://docs.cloud.google.com/run/docs/authenticating/public)
recommends that mechanism for domain-restricted organizations.

The GCP module now disables the check for HTTP services while retaining
`INGRESS_TRAFFIC_INTERNAL_LOAD_BALANCER`. The public route remains the HTTPS
load balancer. Scheduled jobs retain authenticated invocation. Google
provider >= 7.2.0 is required for the field. A regression test checks both
HTTP and scheduled-job boundaries; catalog/planner fixtures were updated.

The same proof website and analytics were then read back successfully on that
new revision. This is a live PostgreSQL write/read and revision-persistence
check, not a claim derived from the heartbeat. Proof state contains only a
website UUID and time. The generated release's own health gate remains a
liveness check; the separate operator proof established database behavior.

The HTTP frontend now returns the generated 301 redirect to HTTPS. During edge
provisioning, the certificate reported `FAILED_NOT_VISIBLE` within overall
`PROVISIONING`, and a GCP-worker probe initially saw HTTP 404/HTTPS reset. DNS,
forwarding rules and certificate attachment were correct; propagation resolved
those transient results without replacing the certificate.

## Limits

GCP worker/cron lanes, promotion, rollback, database restore and cleanup are
NOT EXERCISED by this one-app dev trial. Application-level CA trust and initial
admin rotation were explicit operator steps, not generated Neckbeard automation.
This maintainer-operated trial does not count as an independent beta user.
