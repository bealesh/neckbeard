# GCP Umami trial — 2026-10-22

## Scope

Maintainer-operated trial of Umami upstream commit
`e92fdab99508a8ed05249f6c5f07e140deab79e1` (package 3.4.0) on the GCP
serverless-containers lane. One HTTP service on port 3000, private managed
PostgreSQL 17, Secret Manager, Artifact Registry and HTTPS load balancer.
Redis, ClickHouse and Kafka are optional upstream and are not enabled here.
Only dev is applied; generated stg/prd stacks remain unapplied.

The sandbox display name is `oss-sandbox`; its project ID is
`stock-oss-sandbox` because the shorter ID was globally unavailable. The
sandbox uses the existing Stock organization and billing account. No Stock
application resources or organization policies were modified.

## Organization-policy compatibility

The organization restricts IAM membership to its domain, so an `allUsers`
Cloud Run invoker grant would fail. Its effective policy permits disabling
the invoker IAM check. Google's [public access guidance](https://docs.cloud.google.com/run/docs/authenticating/public)
recommends that mechanism for domain-restricted organizations.

The GCP module now disables the check for HTTP services while retaining
`INGRESS_TRAFFIC_INTERNAL_LOAD_BALANCER`. The public route remains the HTTPS
load balancer. Scheduled jobs retain authenticated invocation. Google
provider >= 7.2.0 is required for the field. A regression test checks both
HTTP and scheduled-job boundaries; catalog/planner fixtures were updated.

## Current limits

Trusted HTTPS and analytics persistence are still pending while the managed
certificate provisions (`FAILED_NOT_VISIBLE` within overall `PROVISIONING`).
Public Google DNS reports the correct IPv4 address and no IPv6/CAA conflict.
Both forwarding rules, the certificate attachment and the HTTP-to-HTTPS
redirect map match the generated plan. An independent GCP-worker probe
(`8228214f-51c3-453e-96fb-4cf2bc2b168b`) received HTTP 404 and an HTTPS reset
while the edge was provisioning. This document must be updated with their actual results
before claiming complete live GCP proof. The heartbeat is liveness-only; it does
not prove PostgreSQL connectivity or analytics writes.

GCP worker/cron lanes, promotion, rollback, database restore and cleanup are
NOT EXERCISED by this one-app dev trial. The generated GitHub release workflow
has not run. Application-level CA trust and initial admin rotation were explicit
operator steps, not generated Neckbeard automation.

## Cost and retained resources

priced **actual HTTPS plan** reports a **$40.63/month modeled baseline**:
$18.73 Cloud SQL, $7.30 global IP, and two $7.30 forwarding rules. Usage-dependent
Cloud Run, traffic, storage, secrets and build charges are additional; this is
not a spending cap or final bill. Only dev resources exist. This difference is
recorded rather than presenting the smaller blueprint number as the live cost.

Bootstrap state remains local and must be retained for cleanup; application
state uses the generated GCS backend. The source bucket, build/initialization
identities, initialization job and private admin/hash secrets are additional
trial resources outside the generated application stack. No cleanup has run;
the sandbox remains billable.
